# NIH Audit (supplement to architecture review) — 2026-06-11

Question examined: how much of the workspace hand-rolls what std / tokio / the
already-imported ecosystem provides, versus custom code justified by real-time
audio, wasm32, or domain constraints.

Method: three passes (infra crates; async/net machinery; parsing/decode/misc),
each comparing hand-rolled subsystems against std and the deps already in
`[workspace.dependencies]`, with an explicit justified/not verdict per site.

## Verdict

The NIH is real but concentrated, not wall-to-wall. Roughly:

- **Infra crates (bufpool, events, platform, storage): mostly justified.**
  The custom CancellationToken (lock-free `is_cancelled()` — tokio_util's takes
  a mutex, which trips RealtimeSanitizer), the sharded RT buffer pool, the
  hierarchical EventBus, and DeferredBus all serve documented RT/wasm
  constraints. Only ~200 LOC of simplification here (wait_range spin loop →
  single `Condvar::wait_timeout`; `CancelGroup` → inline `select_all`; thin
  Mutex wrappers).
- **Parsing/decode: partial.** The ESDS walk in fmp4 is justified (re_mp4
  discards AudioSpecificConfig bytes 3+ needed for HE-AAC); the EWMA estimator
  and the ported cipher are justified. The FLAC box parsing (~150 LOC,
  symphonia-format-isomp4 already does it), generic MP4 box navigation
  duplicating `re_mp4::BoxHeader` (~300 LOC across `mp4/scan.rs` and
  `gapless/mp4.rs`), and trivial hand-written `Display`/`Error`/serde impls
  (~50 LOC vs thiserror/derive_more/serde `rc` feature) are not.
- **Async/net (kithara-net + kithara-stream/dl): this is where the bicycle
  factory lives.** ~2,000–2,500 deletable LOC, detailed below.

Estimated total deletable: **~3,000–3,500 LOC of ~95k**, plus the larger
readability win that the deleted code is precisely the hardest-to-read code
(hand-written poll loops, retry/timeout decorators, slot multiplexers).

## Async/net findings (the real NIH cluster)

| Site | Reinvents | Replacement | Verdict |
|---|---|---|---|
| `kithara-net/src/retry.rs` (~480 LOC w/ tests) | Exponential backoff retry loop, attempt accounting, cancel-aware sleeps | `backon` (or `tower::retry` — tower is already a workspace dep and is **not used by kithara-net at all**) | Not justified. ~400 LOC die. |
| `kithara-net/src/timeout.rs` (95 LOC) | `TimeoutNet` decorator re-stating the whole `Net` trait per method, wasm no-op | inline `tokio::time::timeout` / tower TimeoutLayer; keep the wasm conditional | Mostly not justified. ~80 LOC die. |
| `kithara-net/src/types.rs` | `Headers` = wrapper over `HashMap<String,String>`; `RangeSpec` formatting | `http::HeaderMap` (already transitively present via reqwest), `format!("bytes={start}-{end}")` | Not justified. ~80 LOC die; also fixes case-sensitivity. |
| `kithara-stream/src/dl/registry.rs` + `batch.rs` (~1,000 LOC) | 4-slot priority multiplexer over `Vec<VecDeque<_>>`, manual poll loop, reschedule choreography | `FuturesUnordered`/`JoinSet` + a small priority layer + `Semaphore` | Largely not justified; **caveat:** verify the poll-driven design isn't load-bearing for wasm32 single-thread before replacing. Potentially ~700–900 LOC die. |
| `kithara-stream/src/dl/downloader.rs` (263 LOC) | manual spawn + inflight counter + `AtomicWaker` | `tokio::task::JoinSet` (keep the hang-watchdog as a separate timer) | Partially justified. ~150 LOC die. |
| `kithara-stream/src/dl/response.rs` (175 LOC) | `stream::unfold` + per-chunk `select!` for timeout+cancel | `tokio_stream::StreamExt::timeout()` + `take_until(cancel.cancelled())` | Not justified. ~100 LOC die. |
| `kithara-stream/src/source.rs` + `stream.rs` (~1,600 LOC) | custom `Source` trait (`wait_range`/`read_at`/typed `ReadOutcome`) parallel to `AsyncRead`/`Read` | Keep the typed outcome enum (HLS variant fences and `NotReadyCause` genuinely don't map onto `AsyncRead`), but the sync `Read` adapter + plumbing can shrink | Partially justified. Realistic cut: a few hundred LOC, not the whole layer. |
| `kithara-stream/src/wake.rs` (83 LOC) | arm/flush deferred notify | — | **Justified** (no-syscall produce core). Keep. |

## Recommended sequence

1. **kithara-net diet** (independent, low risk): retry → `backon`, delete
   `TimeoutNet` in favor of inline timeouts, `Headers` → `http::HeaderMap`.
   Net effect: kithara-net becomes a thin reqwest adapter, ~500–600 LOC gone.
2. **Decode plumbing**: delete FLAC manual parsing (symphonia path), rebase
   `mp4/scan.rs` box navigation on `re_mp4` types keeping only the
   gapless-specific logic. ~400 LOC gone.
3. **Boilerplate sweep**: thiserror/derive_more for hand-written impls, serde
   `rc` feature, `hex` crate consistency. ~70 LOC, trivial.
4. **Downloader re-platform** (needs a plan doc + wasm check): JoinSet +
   priority layer instead of registry/batch slot machinery; response stream via
   tokio_stream combinators. This is the big one (~1,000 LOC) and overlaps with
   the "dual state machine peer_done" bug from the main review — replacing the
   machinery fixes that class outright.
5. **Source trait slimming** — only after 4, and only down to the typed-outcome
   core; do not force `AsyncRead` where pending-reason semantics would be lost.

Items 1–3 are safe incremental PRs. Item 4 should follow
`.docs/plans/_template.md` and explicitly state the wasm32 execution-model
constraint before committing to JoinSet.

## What NOT to touch (justified custom code)

- `kithara-platform` rt_cancel (lock-free cancel reads), DeferredBus,
  `dl/wake.rs` — RT-safety is the documented reason and it holds.
- `kithara-bufpool` — app-specific RT pool; no ecosystem equivalent fits.
- EventBus hierarchy — buys real filtering; flattening would move cost to
  subscribers.
- ESDS raw-descriptor walk, EWMA estimator, ported cipher, probe/hang-watchdog
  test macros.
